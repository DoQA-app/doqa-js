# doqa-client: HTTP-клиент DoQA Autotest API для JavaScript

`doqa-client` отправляет запросы к DoQA Autotest API. Его использует адаптер
[`@doqa-tms/jest`](../doqa-jest/README.md). Модуль входит в монорепозиторий `doqa-js`, отдельным
npm-пакетом не публикуется и доступен в пакете `@doqa-tms/jest` по импорту `@doqa-tms/jest/client`.

Клиент отвечает только за HTTP-запросы. Allure-совместимые файлы результатов записывает
[`doqa-js-commons`](../doqa-js-commons/README.md). Модуль не зависит от Jest, поэтому его можно
использовать вне тестового процесса. Для HTTP-запросов, JSON и multipart-запросов с `FormData`
клиент использует `undici`; это единственная зависимость пакета `@doqa-tms/jest` во время
выполнения.

## Требования

- Node.js 22 или 24.

## Установка

Отдельно устанавливать модуль не нужно. Установите адаптер своего фреймворка
(`npm install --save-dev @doqa-tms/jest`), клиент входит в него. Импортировать клиент напрямую
нужно, только если вы пишете собственный адаптер или интеграцию:

```js
const { Client, ApiError } = require('@doqa-tms/jest/client');
```

## Поведение

`Client` отправляет запросы на `<url>/api/autotests/…` и добавляет в каждый запрос токен и
`spaceId`. Суффикс `/api` и завершающие `/` в `url` клиент отбрасывает. Клиент поддерживает JSON и
multipart-запросы (`FormData` из `undici`), прокси, отключение проверки TLS-сертификата и таймауты.

Повторы запросов:

- GET-запросы и запросы, которые вызывающий код пометил как безопасные для повтора (например,
  создание прогона с идемпотентным ключом), повторяются при сетевых ошибках, ответах 5xx и 429;
- остальные запросы повторяются только при ответе 429 и в случае, когда соединение не
  установилось. Если ответ на такой запрос потерян, повтор мог бы создать дубликат прогона или
  результата, поэтому в остальных случаях клиент их не повторяет.

Параметр `retries` задаёт общее число попыток, пауза перед повтором начинается с `retryBackoffMs`
и удваивается с каждой попыткой. После 5 запросов подряд, завершившихся ошибкой, клиент 30 секунд
не обращается к DoQA и сразу завершает запросы ошибкой, затем делает одну пробную попытку.

При ошибке клиент выбрасывает `ApiError`. Её поле `status` содержит HTTP-код ответа или `0`, если
DoQA не ответил. Сообщение содержит метод, URL без query-параметров, код ответа и первые 500
символов тела ответа. Токен в сообщениях заменяется на `***`.

После работы с клиентом вызовите `await client.close()`.

## Использование

```js
const { Client } = require('@doqa-tms/jest/client');

const client = new Client({
  url: process.env.DOQA_URL,
  token: process.env.DOQA_TOKEN,
  spaceId: process.env.DOQA_SPACE_ID,
  requestTimeoutMs: 30000,
  retries: 3,
  retryBackoffMs: 500,
});
try {
  const plan = await client.request('test-runs/123/autotests', {}, 'GET');
} finally {
  await client.close();
}
```

Код примера выполняйте внутри async-функции. `ApiError` наследует `Error`. Модуль доступен как
CommonJS и ES-модуль и содержит объявления типов TypeScript.

## Сборка и тесты

Модуль собирается из корня монорепозитория `doqa-js`:

```sh
npm run build
node --test doqa-client/tests/*.test.cjs
```

Тесты проверяют клиент на локальном HTTP-сервере, который слушает loopback-адрес; доступ в сеть
не нужен.
